# 과제 08: MST 알고리즘 비교 (Kruskal vs Prim)

정점 50개 가중치 무방향 그래프를 희소(간선 100개) 및 밀집(간선 600개) 환경으로 구축하고, 인접 리스트 기반 Kruskal 알고리즘과 인접 행렬 기반 Prim 알고리즘을 각각 적용하여 메모리 사용량과 실행 시간을 비교 분석한 보고서다.



## 1. 실행 방법

gcc -Wall -Wextra -o mst main.c
./mst          # seed 1234 (기본)
./mst 7        # seed 변경 가능

- 희소 및 밀집 그래프는 각각 1회 생성하여 동일한 그래프 구조를 인접 리스트(Kruskal)와 인접 행렬(Prim)에 똑같이 적용했다.
- 모든 그래프는 연결 그래프(Connected Graph)가 되도록 정점 1부터 49까지 앞쪽 정점 중 하나와 연결하여 기본 스패닝 트리를 먼저 형성한 후, 나머지 간선을 무작위로 추가했다. 생성 후 DFS를 통해 완전 연결성을 재확인했다.
- 간선 가중치는 1부터 100 사이의 무작위 정수다.
- seed 1부터 10까지 테스트한 결과 모든 시도에서 정확히 49개의 MST 간선이 선택되었으며 Kruskal과 Prim의 총 가중치 비용이 동일함을 확인했다.

---

## 2. 측정 방법

- 실행 시간: MST 계산 수행 구간만 clock() 함수로 측정했다. 단일 실행 시간이 수 마이크로초(us) 단위로 매우 짧아 오차를 줄이기 위해 20,000회 반복 실행한 평균값을 산출했다.
  단위는 us(마이크로초)다. Kruskal의 경우 인접 리스트에서 간선 추출, 정렬, Union-Find 연산 과정이 모두 시간에 포함된다.
- 메모리 사용량: sizeof 연산자 기준으로 산출했다.
  - Kruskal: 인접 리스트(head 배열 + 노드 2E개 x 16B) + 정렬용 간선 배열(E x 12B) + Union-Find(parent, rank) + MST 결과 간선 배열(49개)
  - Prim: 인접 행렬(50x50 int) + key, pre, in_mst 배열

## 3. 실험 결과 (seed 1234 기준)

| Case | 그래프 | 표현 방식 + 알고리즘 | MST 간선 수 | MST 비용 | 메모리 | 실행 시간 |
| :---: | :--- | :--- | :---: | :---: | :---: | :---: |
| 1 | 희소 (E=100) | 리스트 + Kruskal | 49 | 1419 | 5,788 B | 6.341 us |
| 2 | 밀집 (E=600) | 리스트 + Kruskal | 49 | 238 | 27,788 B | 58.975 us |
| 3 | 희소 (E=100) | 행렬 + Prim | 49 | 1419 | 10,600 B | 15.664 us |
| 4 | 밀집 (E=600) | 행렬 + Prim | 49 | 238 | 10,600 B | 17.522 us |

- 실행 시간 편차: 동일 seed 기준 3회 재측정 시 Case 1은 6~9 us, Case 2는 59~69 us, Case 3은 14~17 us, Case 4는 14~19 us 범위를 보였다.
  따라서 Case 3과 Case 4의 차이(15.7 us vs 17.5 us)는 측정 오차 범위 내로 볼 수 있으며, 희소/밀집 간 차이 및 알고리즘 간 명확한 수치 차이를 중심으로 해석한다.
- 동일 그래프 조건에서 Kruskal과 Prim의 최종 MST 가중치 비용은 정확히 일치했다 (희소 1419, 밀집 238).

## 4. 분석 및 고찰

### 4-1. 메모리 사용량 분석

- Prim + 인접 행렬 방식은 간선 수(E) 변동과 무관하게 50x50 고정 크기 행렬을 유지하므로 희소와 밀집 모두 10,600 B로 일정하다.
- Kruskal + 인접 리스트 방식은 간선 수가 증가함에 따라 메모리가 선형적으로 증가한다. 희소 그래프 환경에서는 5,788 B로 행렬 방식의 절반 수준이었으나,
  밀집 그래프 환경에서는 27,788 B로 늘어나 행렬 대비 약 2.6배의 메모리를 소비했다. 이는 간선 1개 추가 시 인접 리스트 노드 2개(32 B)와 정렬용 간선 배열 요소(12 B)가 더해져 총 44 B씩 증가하기 때문이다.
- 구조체 크기 기준 산출식인 약 (1388 + 44 x E) Bytes를 적용하면, 정점 50개 환경에서는 간선 수(E)가 약 210개를 초과하는 시점부터 인접 행렬 기반 Prim의 메모리 효율이 인접 리스트 기반 Kruskal보다 우수해진다.

### 4-2. 실행 시간 분석

- Kruskal 알고리즘: 간선 정렬 단계가 전체 수행 시간을 주도하므로 간선 수의 영향을 크게 받는다. 간선 수가 100개에서 600개로 6배 증가했을 때 실행 시간은 6.341 us에서 58.975 us로 약 9.3배 증가했다.
   이는 정렬 복잡도인 O(E log E)에 비례하여 시간이 증가했음을 나타낸다.
- Prim 알고리즘: 인접 행렬 방식으로 구현되어 최소 key 값을 갖는 정점을 찾기 위해 매 단계마다 전체 50개 정점을 탐색하므로 복잡도가 O(V^2) 형태를 가질 수밖에 없다.
   간선 수 변동에 따른 영향이 적어 희소(15.664 us)와 밀집(17.522 us) 환경에서 거의 유사한 실행 시간을 기록했다.
- 상호 비교: 간선 수가 적은 희소 그래프에서는 Kruskal이 Prim보다 약 2.5배 빨랐으나, 간선 수가 많은 밀집 그래프에서는 Prim이 Kruskal보다 약 3.4배 빨랐다.

### 4-3. 그래프 밀도의 영향 요약

- 희소 그래프 (E=100): 인접 리스트 + Kruskal 조합이 메모리 사용량과 실행 시간 모든 면에서 우수했다. 인접 행렬 + Prim 방식은 간선 밀도가 낮은 상태에서도 50x50 행렬 전체를 탐색해야 하므로 연산 낭비가 발생했다.
- 밀집 그래프 (E=600): 인접 행렬 + Prim 조합이 메모리 사용량과 실행 시간 모든 면에서 우수했다. Kruskal 방식은 600개의 간선을 정렬하는 연산 부하로 인해 실행 시간이 크게 늘어났다.
- MST 비용 차이: 동일 정점 수에서 희소 그래프의 MST 비용(1419)이 밀집 그래프(238)보다 훨씬 높게 측정되었다
   이는 밀집 그래프일수록 선택 가능한 간선의 후보가 많아져 상대적으로 가중치가 작은 간선들만으로 스패닝 트리를 구성할 수 있기 때문이다.

---

## 5. 한계점 및 고려사항

- 복합 조건 비교의 한계: 본 실험은 자료구조(인접 리스트/인접 행렬)와 알고리즘(Kruskal/Prim)을 하나의 세트로 묶어 비교했기 때문에,
  성능 차이가 자료구조 접근 방식에서 기인한 것인지 알고리즘 자체의 구조에서 기인한 것인지를 독립적으로 분리하여 측정하지는 못했다 (예: 인접 리스트 기반 Prim 미측정).
- 측정 환경 변수: 실행 시간은 실행 장비의 스펙 및 컴파일러 최적화 옵션에 따라 달라질 수 있으며, 본 수치는 별도의 컴파일 최적화 옵션 없이 측정한 결과다.
- 메모리 계산 범위: 메모리 사용량은 sizeof 연산자 기준 수치이며, 동적 메모리 할당(malloc) 시 내부적으로 소비되는 운영체제 관리용 헤더 영역의 크기는 반영되지 않았다.
